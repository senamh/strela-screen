# Публикация Strela Screen

Публикация разрешена только в `senamh/strela-screen`. Репозиторий публичный; перед отправкой изменений проверьте состав коммита. Записи пользователей, `.strela`-проекты, ключи доступа и содержимое `work/` не включаются в выпуск.

## Подготовка

Обновите одинаковую версию в `package.json`, `package-lock.json` и `ui/manifest.json`, затем сведения в `RELEASE_NOTES.md`, `QA.md` и инструкции. Зафиксируйте предназначенные для выпуска изменения в `main`. Чистая рабочая копия необходима для связи результатов тестов с точным коммитом.

Одна команда заново собирает расширение, выполняет все автоматические тесты и создаёт архивы:

```sh
npm run release:prepare
```

В `outputs/` создаются:

- `strela-screen-<version>.zip`: готовая папка расширения для пользователя и Gumroad;
- `strela-screen-<version>-store.zip`: структура для подачи в магазин, не подтверждение одобрения;
- `SHA256SUMS` и `release-manifest.json`: размеры, SHA-256 обоих архивов, версия и идентификатор сборки;
- `release-validation.json`: подтверждение локальных тестов с полным SHA коммита;
- `GUMROAD_UPLOAD.md`: точный файл для загрузки, контрольная сумма и порядок проверки.

Порядок файлов, время записей ZIP и атрибуты фиксированы. Одинаковые входные файлы дают побайтово одинаковые архивы независимо от часового пояса. Перед упаковкой проверяется актуальность сборки, всех документов, статических файлов и лицензий. Неожиданные файлы и символические ссылки запрещены.

Для проверки промежуточных изменений до коммита доступны прежние `npm run build`, `npm test`, `npm run package`. Они не заменяют подтверждение `release:prepare` для публикации. Команда `node scripts/release.mjs` выполняет только локальную проверку готовых файлов, без сетевых действий.

## GitHub

После успешной подготовки отправьте проверенный коммит и явно запустите публикацию с полным SHA, указанным в результате подготовки:

```sh
git push origin main
npm run release:publish -- <полный-SHA-проверенного-коммита>
```

Используется существующий вход `gh` или Git credential helper. Не передавайте токен в аргументах и не сохраняйте его в проекте. При отсутствии входа публикация останавливается.

Перед публикацией проверяются чистая ветка `main`, подтверждение тестов, неизменность архивов и описания, соответствие удалённой `main` и тега проверенному коммиту. Сначала создаётся черновик выпуска, затем загружаются два ZIP, manifest и контрольные суммы. После проверки всех файлов выпуск становится публичной бета-версией. Все четыре опубликованных файла скачиваются повторно и сравниваются с локальными побайтово.

При повторном запуске допускаются только идентичные файлы. Опубликованные вложения и теги не заменяются. Изменение уже опубликованного пакета требует новой версии. Прерванную загрузку можно повторить той же командой при неизменных файлах и коммите. Не удаляйте черновик, не проверив причину остановки.

Отдельная проверка не выполняет внешних изменений:

```sh
npm run release:verify
```

Эта проверка относится к текущей подготовленной версии и требует, чтобы её коммит оставался текущим в локальной и удалённой `main`. Это не система проверки произвольных исторических выпусков. Результат локальных тестов не является результатом CI или проверкой Windows, установленного расширения либо физического iPhone.

## Gumroad

Следуйте `outputs/GUMROAD_UPLOAD.md`. В существующий продукт загружается тот же пользовательский ZIP, который проверен на GitHub. Сохраните бесплатную цену, настройки аккаунта и предыдущий пакет. Измените версию в описании, сохраните изменения, полностью перезагрузите страницу содержимого и проверьте сохранённое вложение. Затем проверьте публичную страницу. Не считайте локальный `blob:`-адрес подтверждением сохранения на сервере.

Работа в Gumroad намеренно отделена от GitHub: сценарий не извлекает cookies браузера, не изменяет цену и не отправляет письма покупателям. При доступности скачивания проверьте контрольную сумму полученного ZIP. Если подтверждено только сохранение вложения, укажите именно этот результат, а не побайтовую проверку загрузки.

## Возврат к предыдущему выпуску

Если установка, открытие проекта или экспорт перестали выполняться, укажите предыдущую проверенную версию как рекомендуемую и добавьте предупреждение к проблемному выпуску. Не удаляйте прежние релизы и не заменяйте их архивы. Для обновления и возврата сначала сохраните `.strela`-копии проектов, затем замените файлы в прежней папке расширения и нажмите перезагрузку в браузере. Не удаляйте расширение: это может привести к потере локальных проектов.
