# Strela Screen 0.6.0: focus corrections, content protection and responsive processing

Experimental public browser beta. Download the release ZIP and load the unpacked extension; this is not an approved extension-store listing or a signed desktop app.

## Changes in 0.6.0

- The editor and extension popup display a reproducible build identifier. It also ships in `build-info.json`, distinguishing local builds with the same version number without uploading diagnostic data.
- Thumbnail decoding no longer competes with analysis/export. Busy operations and project replacement release its decoder; explicit cancellation prevents it from restarting in the background. Late results cannot replace a newly opened project's thumbnails, including reopening the same project ID. After explicit cancellation, missing thumbnails can be regenerated by reopening the project.
- Graphite interface with restrained red accents, stronger control contrast and grouped settings. Record and Import video are directly above the preview. Video backgrounds are unchanged.
- Demo generation runs in a dedicated worker and can be cancelled. Worker jobs release resources on success, cancellation, runtime errors and message-transfer failures.
- Paused previews no longer repaint unchanged frames continuously; preview rendering pauses during processing. Starting a busy operation stops playback so timeline cuts are not bypassed while packaging a project.
- Failed analysis no longer silently leads to an automatic export. The source remains available, with a clear retry/manual-export message. Failed re-analysis preserves existing focus points. Export startup and message-transfer errors restore editable controls.
- Select a focus chip to edit its source time, hold (0.2–30 playback seconds) and zoom (1–3). Apply focus commits all values; normal keyboard changes also apply on leaving a field. Move in preview relocates the selected point; removal is a separate action. The next focus takes precedence over a longer hold.
- Choose a protected source rectangle by dragging or entering percentages. It remains included throughout the video, including transitions. If it cannot fit at the requested aspect, it is contained with additional background space, never stretched. Protected crops have square corners so corner text is not clipped. A large protected region limits magnification.
- Protect reading/narration intervals with Keep original pace. Focus holds and recorded click intervals are also excluded from automatic pause speed-up. Static frames alone cannot distinguish reading from idle time. Speed-up remains off by default.
- Analysis v5 filters repeated reversible changes using five alternating, similar redraws. Growing text and progress remain candidates. Distinct distant actions can generate separate focus points one second apart. Re-running analysis preserves manual replacements without duplicating their original automatic cues.
- Twenty deterministic synthetic screen-change scenarios are retained for regression testing. They do not constitute testing on twenty real application recordings. See QA.md for verification boundaries.

The extension package is `strela-screen-0.6.0.zip`; the store-layout archive is not evidence of store approval. Back up `.strela` projects before updating. Existing projects remain supported.

## What's new

- **Speed up pauses (optional).** Turn on **Speed up pauses** to play stretches of 3 seconds or more where nothing on screen changes up to 16× faster. This is visual stillness detection, not a guarantee that all typing, cursor movement or reading is recognized. Your clips are not changed, and the sped-up parts are silent. Off by default. On an 8-minute Blender recording it found 19 pauses (83 seconds), mostly render waits.
- **Frame rate that matches the source.** Recordings near 25 or 50 fps now render at 50 fps instead of 60, which repeated every fifth frame; the export window marks the matching option.
- **Continuous follow.** While the frame holds an action, work that drifts towards the edge moves it part of the way, smoothly. A change far from the current action is followed only when a second change confirms it, so one-off redraws elsewhere on screen do not pull the frame away.
- **Faster exports of trimmed MP4s.** Skipped parts are no longer decoded: a 50-second clip starting at 4:10 exported in 25 s instead of about 45 s.
- **Icons** for the toolbar and extensions page, and a [privacy policy](https://github.com/senamh/strela-screen/blob/main/PRIVACY.md).

Projects from earlier versions can use pauses after **Generate auto-focus** re-runs the analysis.

## Download and install

Use **strela-screen-0.6.0.zip** for this local build, not an automatically generated source-code ZIP.

1. Extract the archive.
2. Open `chrome://extensions` (or `edge://extensions`).
3. Enable Developer mode → **Load unpacked** → select the extracted **strela-screen** folder containing `manifest.json`.
4. Open Strela → **Open studio** → **Import** a video, or **Try a demo**.
5. Wait for analysis and rendering. The MP4 downloads as `<project> - Strela.mp4` when it is ready.

**Updating:** back up `.strela` projects, replace the files in the existing extension folder, press reload on Strela in `chrome://extensions` and reopen the studio. Do not uninstall it if you want to keep its local library. **Save project** downloads a `.strela` project backup, not a video.

The archive includes Russian installation instructions, third-party notices and a test/limitations report.

## Before you try it

This is an **experimental browser beta**, not a signed desktop installer or a Chrome Web Store release. Intended for current Chrome/Edge. macOS Chrome studio checks have passed; Windows/Edge and the sideloaded extension permission paths still need qualification. Safari/Firefox are unsupported.

Analysis detects visual changes. It is not OCR, semantic understanding or guaranteed cursor tracking, so review generated focus. Small text needs a sharp source; increasing output resolution cannot restore missing detail. File sizes depend on how much the screen changes.

**Verification:** build `9d8671e5ad00` passes 95 automated tests. On 17 September 2026, a real 2560×1440 screen recording completed automatic analysis and full-length MP4 export: 97 focus points, 1206×2622 at 50 fps, 477.04 s and 476.2 MiB. The source has no audio track; silent output is expected. The browser decoded the output and displayed sampled frames without errors. Automatic focus still requires review. Earlier audio/pause checks are historical evidence, not current Windows, installed-extension or physical-iPhone qualification. See QA.md.

Report a reproducible problem through GitHub Issues. Include browser/OS, error message and a non-sensitive sample when possible. Do not attach private screen recordings publicly.
